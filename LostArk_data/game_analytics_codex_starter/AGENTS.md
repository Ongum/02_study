# Repository agent rules

Read `CODEX_MASTER_PROMPT.md`, `docs/PRODUCT_BRIEF.md`, `docs/ARCHITECTURE.md`, `docs/DECISIONS.md`, `docs/ROADMAP.md` before changes. Follow their confirmed decisions and mark proposals as proposals. Never create or update paid GCP resources without explicit approval. Never log API keys, usernames, full Steam author IDs, or secrets. Never claim test/deployment success unless actually verified. No API ToS bypass. Use precise logs, schema and unit tests. Prefer Python 3.11+, typed functions, pytest, configuration-driven connectors, and dependency-light modules. Keep the pipeline idempotent. Store raw responses with provenance; support deletion/retention policy and access controls. New public data source must have documented legitimacy and constraints. Keep per-domain marts separate while reusing utilities. All results must be distinguishable as measured, illustrative, simulated, or planned. Every meaningful design decision goes to `docs/DECISIONS.md` / ADR. Finish each implementation with reproduction instructions and any unverified assumptions.
